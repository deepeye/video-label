# 视频语料标注平台 Demo · Step4 视频打点工作台设计

> 版本：v1.0 · 2026-06-23  
> 来源：`docs/视频语料标注平台 · 演示 Demo PRD.md`（v2.0-demo）+ 本轮确认的交互方向  
> 目标：将现有 Step4「审核台」替换为「视频打点交互 demo」，突出关键事件定位与分析能力

---

## 0. 本文解决什么问题

当前 Demo 的 Step4 以「框审核」为主，能体现人机协同，但不够贴近“视频内容关键事件定位与分析”的叙事。

本设计将 Step4 替换为一套**视频打点工作台**：

- 用户可对视频内容创建**单点事件**或**时间段事件**
- 事件可填写**事件类型、严重级别、标签、描述**
- 事件可选绑定一个**画面区域框**
- 事件在**视频区、时间轴、右侧列表**三处联动
- 仍保持 Demo 的核心约束：**纯前端、零后端、可重置、可撤销、适合 5 分钟演示**

本文只覆盖 Step4 的业务语义与交互设计；Step1/2/3/5、外层 Demo 控制条、全局步骤条继续沿用现有骨架。

---

## 1. 已确认决策

| 维度 | 决策 |
|---|---|
| Step4 形态 | **直接替换**现有 Step4 审核台 |
| 核心能力 | 同时支持**单点打点**与**时间段打点** |
| 区域标记 | **可选绑定**矩形框，不强制 |
| 右侧字段 | 偏**业务化 demo**：事件类型 / 严重级别 / 标签 / 描述 / 时间 |
| 创建方式 | **时间轴快速创建为主**，右侧按钮兜底 |
| 事件类型 | **预置类型 + 可自定义输入** |
| 复杂度边界 | 不做跟踪、不做 polygon、不做多框、不做多片段 |

这些决策全部服务于一个目标：**让客户在 30~60 秒内看懂“视频打点”的价值，并且能亲手操作成功。**

## 2. 整体体验目标

### 2.1 成功体验

客户进入 Step4 后，应当能在一次演示中自然完成以下动作：

1. 播放视频并拖动到关键位置
2. 在时间轴上创建一个单点事件
3. 再拖出一个时间段事件
4. 在右侧填写事件类型、严重级别、标签、描述
5. 给某个事件补一个画面矩形框
6. 在事件列表、视频、时间轴之间来回定位与回看

如果以上链路能稳定完成，Demo 就成功传达了：

> 这不是单纯“看视频”，而是在对视频中的关键事件做结构化定位和分析。

### 2.2 非目标

本设计明确不追求：

- 生产级逐帧标注效率
- 高精度跨帧目标跟踪
- 多人协作审核流
- 复杂筛选、批量编辑、批量导入
- 多几何类型（polygon / polyline / brush）

## 3. 工作台结构

Step4 保持现有三段式骨架，但替换内部语义。

### 3.1 布局总览

```text
+--------------------------------------------------------------------------------+
| 顶部工具条：视频打点 | 浏览 | 单点 | 时间段 | 框选 | 播放/暂停 | 1x/2x | 时间 | 撤销 |
+--------------------------------------------------------------------------------+
|                                                                                |
|                           中央视频区（主视觉）                                  |
|                  视频画面 + 当前事件高亮框 + 框选态草框                         |
|                                                                                |
+--------------------------------------------------------------------------------+
| 底部时间轴：播放头 / 刻度 / 单点事件 / 时间段事件 / 创建交互                    |
+----------------------------------------------+---------------------------------+
| 事件列表                                     | 事件编辑表单                    |
| 时间排序 / 高亮选中 / 跳转定位               | 类型 / 严重级别 / 标签 / 描述   |
|                                              | 时间 / 区域框状态 / 删除        |
+----------------------------------------------+---------------------------------+
```

### 3.2 顶部工具条

字段与职责：

- 标题：`视频打点`
- 模式切换：`浏览 / 单点 / 时间段 / 框选`
- 播放控制：`播放 / 暂停`
- 速度：`1x / 2x`
- 时间显示：`当前时间 / 总时长`
- 撤销：撤销上一步事件操作

原则：

- 同一时刻仅允许一个主模式生效
- 创建完成后自动退回浏览模式，降低用户迷失风险
- 框选模式仅在已有选中事件时可进入

### 3.3 中央视频区

中央区的职责是**回看与区域定位**，不是主创建入口。

呈现内容：

- 本地视频播放画面
- 当前选中事件的矩形框（如果有）
- 框选模式下的拖拽草框
- 左上角轻量 badge：显示当前事件类型与严重级别

约束：

- 默认不显示复杂辅助线和过多工具
- 不做多事件同时框选高亮，避免画面太乱
- 若选中事件没有区域框，则视频仅作为回看背景

### 3.4 底部时间轴

时间轴是 Step4 的**主交互区**，承担事件创建、定位、回看三种责任。

视觉表达：

- 播放头：竖线
- 单点事件：圆点或细竖线
- 时间段事件：彩色条带
- 当前选中事件：高亮边框/加深填充
- hover：显示事件摘要 tooltip

交互：

- 浏览模式：拖动播放头、点击已有事件选中
- 单点模式：点击空白处创建单点事件
- 时间段模式：按下拖拽生成区间事件
- 点击已有事件：跳到其锚定时间并同步右侧选中

原则：

- 主创建动作必须发生在时间轴上，建立“事件属于时间”的心智
- 时间轴空白处的点击和拖拽反馈必须即时，不能让用户怀疑是否创建成功

### 3.5 右侧面板

右侧面板拆成两段：

#### 上半区：事件列表

每条事件显示：

- 事件类型名称
- 时间点或时间段
- 严重级别颜色
- 是否有区域框

行为：

- 按时间排序
- 点击列表项：选中事件并跳到对应时间
- 当前事件高亮

#### 下半区：事件编辑表单

字段：

- 事件类型：预置下拉 + 可自定义输入
- 严重级别：高 / 中 / 低
- 标签：自由输入，多值
- 描述：一句话说明关键事件
- 时间：单点 `timeMs` 或 区间 `startMs/endMs`
- 区域框状态：无 / 已绑定
- 删除按钮

原则：

- 右侧负责“结构化填写”，不负责复杂创建
- 创建完成后自动聚焦到事件类型字段，便于主讲连续演示

## 4. 核心交互流

### 4.1 创建单点事件

主路径：

1. 切到`单点`模式
2. 点击时间轴空白处
3. 立即创建一条新事件
4. 默认事件类型为空，右侧进入编辑态
5. 自动切回`浏览`模式

兜底路径：

1. 点击右侧“新增事件”
2. 取当前播放头时间创建单点事件
3. 进入编辑态

### 4.2 创建时间段事件

主路径：

1. 切到`时间段`模式
2. 在时间轴按下并拖拽
3. 松手后生成区间事件
4. 右侧进入编辑态
5. 自动切回`浏览`模式

兜底路径：

1. 右侧新增事件
2. 以当前时间为起点，默认给一个短区间
3. 用户再修改结束时间

### 4.3 编辑事件

编辑行为包括：

- 选择预置事件类型
- 输入自定义事件类型
- 设置严重级别
- 添加/删除标签
- 编辑描述
- 修改时间点或起止时间
- 单点与时间段相互转换

转换规则：

- 单点 → 时间段：保留当前 `timeMs` 作为 `startMs`，给一个默认短结束时间
- 时间段 → 单点：收缩为 `startMs`

### 4.4 绑定区域框

区域框是增强能力，不是主链路。

流程：

1. 先选中某事件
2. 点击“添加区域框”或切到`框选`模式
3. 在视频上拖出一个矩形框
4. 保存后事件状态变为“已绑定区域”
5. 自动回到浏览模式

设计约束：

- 一个事件**最多一个矩形框**
- 单点事件：框绑定到 `timeMs`
- 时间段事件：框默认绑定到 `startMs`
- 不做关键帧插值
- 不做跨帧漂移或连续跟踪

### 4.5 三处联动规则

同一事件在三处联动：

- **时间轴**：显示位置和选中态
- **右侧列表**：显示摘要和编辑入口
- **视频区**：显示区域框

联动规则：

- 点击时间轴事件 → 列表高亮 + 视频跳转
- 点击列表项 → 播放头跳转 + 视频高亮框
- 点击视频区矩形框 → 列表与时间轴同步选中

## 5. 状态模型设计

## 5.1 设计原则

不要强行复用当前 Step4 的 `annotation / track / keyframe / review` 语义。

原因：

- 当前模型围绕“机器框审核”设计
- 视频打点的核心对象是“事件”，不是“目标轨迹”
- 若硬复用，会导致创建、列表、时间段、事件类型这些语义非常别扭

因此，建议：

- **外层仍沿用现有 Zustand store 架构、reset、undo 能力**
- **Step4 内部业务模型切换为 event markers**

### 5.2 事件模型

```ts
interface EventMarker {
  id: string;
  eventType: string;
  customEventType?: string | null;
  severity: 'high' | 'medium' | 'low';
  tags: string[];
  description: string;
  mode: 'point' | 'range';
  timeMs: number | null;
  startMs: number | null;
  endMs: number | null;
  regionBox?: [x: number, y: number, w: number, h: number] | null;
  regionAnchorMs?: number | null;
}
```

说明：

- `eventType`：预置类型值
- `customEventType`：当选择“自定义”时使用
- `mode` 决定使用单点还是区间字段
- `regionBox` 可为空
- `regionAnchorMs` 记录区域框所属时间

### 5.3 Step4 UI 状态

```ts
interface Step4EventState {
  events: EventMarker[];
  selectedEventId: string | null;
  timelineTool: 'browse' | 'point' | 'range' | 'region';
  currentTimeMs: number;
  draftRange: { startMs: number; endMs: number } | null;
  draftRegionBox: [number, number, number, number] | null;
}
```

### 5.4 Store action 建议

```ts
createPointEvent(timeMs)
createRangeEvent(startMs, endMs)
updateEvent(id, patch)
deleteEvent(id)
selectEvent(id | null)
setTimelineTool(tool)
setCurrentTimeMs(ms)
attachRegionBox(id, box, anchorMs)
removeRegionBox(id)
undo()
reset()
```

### 5.5 初始数据策略

初始快照里建议预置少量事件，便于演示一进入就不是空白：

- 1 个单点事件
- 1 个时间段事件
- 至少 1 个事件带区域框

这样主讲既可以演“编辑已有事件”，也可以演“新增事件”。

## 6. 预置事件类型与业务字段

### 6.1 预置类型

建议默认给出 5 个事件类型：

- 碰撞
- 急刹
- 行人出现
- 车道偏移
- 异常停留

另加一个：

- 自定义

原则：

- 名称必须一眼可懂
- 足够像真实业务，但不需要行业过深
- 允许现场根据客户语境改成别的说法

### 6.2 严重级别

固定三档：

- 高
- 中
- 低

用途：

- 时间轴颜色区分
- 列表项颜色提示
- 视频区 badge 色彩表达

### 6.3 标签

标签做自由输入即可，不需要复杂候选系统。

示例：

- 夜间
- 遮挡
- 高风险
- 车辆
- 路口

### 6.4 描述

描述坚持一句话原则，用于表达“这个事件为什么重要”。

例如：

- 前车右后保险杠出现明显擦碰痕迹
- 车辆在路口前出现急刹减速过程
- 行人进入盲区边缘，需要重点关注

## 7. 演示脚本建议

这一步不是实现代码，而是约束交互设计必须支持什么样的话术。

建议 Step4 的主讲链路如下：

1. 进入 Step4，视频停在一个合适位置
2. 主讲说明：“这里我们不是只看视频，而是对关键事件做结构化打点”
3. 切到单点模式，在时间轴点一下，创建一个事件
4. 选择事件类型“碰撞”，补一句描述
5. 切到时间段模式，在时间轴拖一段，创建过程事件
6. 设为“异常停留”或“急刹过程”
7. 选中事件，添加区域框，在画面上框出关注位置
8. 回点事件列表项，证明事件可快速定位与复看

要求：

- 30~60 秒内必须能完整演完
- 主路径不能依赖隐藏入口
- 每一步反馈必须明显

### 8.2 需要替换的部分

- review status

### 8.3 Step5 导出调整

导出内容要从“审核后的 annotations”转向“事件打点结果”。

建议导出主对象：

```ts

  videoMetadata: {...};
  events: EventMarker[];
  exportedAt: number;
}
```

原则：

- 导出要真可下载
- 结构要清晰到客户可理解
- 不需要伪装成生产训练 schema
- 但必须足够结构化，能体现系统能力

## 9. 状态机与模式边界

### 9.1 主模式

主模式只有四个：

- `browse`
- `point`
- `range`
- `region`

### 9.2 模式规则

- 默认进入 `browse`
- `point` 创建成功后自动退回 `browse`
- `range` 创建成功后自动退回 `browse`
- `region` 只有在 `selectedEventId !== null` 时可进入
- 删除当前选中事件后，自动清空选中并回 `browse`

### 9.3 风险规避

禁止出现以下状态混乱：

- 同时在创建时间段又在框选
- 没有选中事件却允许添加区域框
- 创建完事件后仍停留在创建模式，导致用户误连点新增
- 时间轴正在拖拽时右侧表单写回又触发跳转

这意味着实现时要把“主模式唯一”作为硬约束，而不是靠组件层互相判断。

## 10. 测试策略

### 10.1 单元 / 集成测试

必须覆盖：

- 时间轴点击创建单点事件
- 时间轴拖拽创建时间段事件
- 右侧表单修改会写回 store
- 列表点击会同步 `selectedEventId` 与 `currentTimeMs`
- 区域框保存后写入事件
- `undo()` 可撤销新增 / 编辑 / 删除 / 区域框绑定
- `reset()` 恢复初始快照

### 10.2 E2E

至少覆盖三条黄金路径：

1. 新建单点事件并填写类型与描述
2. 新建时间段事件并回点定位
3. 给事件补一个矩形框并导出结果

### 10.3 不强求测试的部分

- 精细像素级 UI 外观
- tooltip 文案
- hover 态动画细节

目标是保证 demo 稳，而不是把全部视觉细节都写成脆弱测试。

## 11. 实现边界与拆分建议

为了降低风险，建议把 Step4 改造拆成下面几个清晰单元：

- `Step4Timeline.tsx`：底部时间轴与事件创建
- `Step4VideoStage.tsx`：视频区与区域框
- `Step4EventList.tsx`：右侧事件列表
- `Step4EventEditor.tsx`：右侧表单编辑
- `step4EventStore` 相关 actions：事件状态写回

原则：

- 每个单元只负责一个明显目的
- 时间轴逻辑与表单逻辑分离
- 视频区只关心显示和框选
- 避免把全部交互都塞回一个超大的 `ReviewCanvas.tsx`

---

## 12. 最终建议结论

本次 Step4 改造应定为：

- **把现有 Step4 审核台直接替换为视频打点工作台**
- **以时间轴为主交互区**
- **以事件为核心数据模型，而不是审核框/轨迹模型**
- **区域框是可选增强，不做跟踪与插值**
- **保证 30~60 秒内能完成一次完整事件打点演示**

如果后续需要扩展到更真实的标注平台，再在这个模型上增加：多区域、多时间片段、跟踪、筛选、批量操作。

但这一版 demo 不需要，也不应该提前实现这些能力。
